HIGH · 1
Pillow 12.3.0 - 39 CVEs on the untrusted-image decode path · requirements.txt

The board decodes base64 images posted by any registered agent through PIL (app/images.py: decode() - Image.open + verify() + load()). Pillow 12.3.0 carries 39 disclosed vulnerabilities, all fixed in 13.0.0.

Evidence (representative CVEs)

PYSEC-2026-4328  heap use-after-free in libtiff tag rejection
PYSEC-2026-4327  out-of-bounds read in P;2L / P;4L raw decoders
PYSEC-2026-4326  invalid storage dereference in rank-based filters
PYSEC-2026-4343  unchecked 32-bit WMF/EMF dimensions (Windows)
PYSEC-2026-4339  multi-frame loaders retain ImagingCore allocation

Why it matters here

The app's own guard (raster-only formats, 10 MiB byte cap, 20 MP pixel cap, SVG rejected) stops decompression bombs and active formats - it does not stop memory-safety bugs inside the C decoders. Reachability: POST /api/messages with image_attachment, and board registration is open by default (see info finding). A malicious agent can crash the board process; several of the CVE classes are memory-corruption primitives.

requirements.txt:  Pillow==12.3.0 -> Pillow==13.0.0
verify: python -c "import PIL; print(PIL.__version__)"
MEDIUM · 1
Starlette 0.41.3 - Host-header injection reaches request.base_url used in 7 places · requirements.txt (transitive via fastapi==0.115.6)

PYSEC-2026-161 / PYSEC-2026-248: unvalidated Host header flows into request.url / request.base_url. bot_board uses request.base_url at 7 call sites, the sensitive one being app/main.py:593 - /agents.md, the onboarding document that tells every bot where the board lives:

text = text.replace("http://127.0.0.1:8080", str(request.base_url).rstrip("/"))

Reachability & honest impact

The poisoned URL only lands in the attacker's own response, so direct impact is nil for a bot that connects by its configured address. It becomes real behind a caching proxy (a poisoned response served to everyone) or when a launcher fetches /agents.md through an attacker-provided URL. Rated medium for impact ceiling, not likelihood.

Also in this version (not reachable here)

Range-header quadratic DoS (PYSEC-2026-1942), StaticFiles Windows realpath (PYSEC-2026-2281), HTTPEndpoint dispatch (PYSEC-2026-2280), multipart form DoS (PYSEC-2026-1941/249) - no StaticFiles/FileResponse/HTTPEndpoint/form parsing in this codebase.

Upgrade FastAPI to a release pinning starlette >= 0.49.1 (covers host-header fix);
ideally current fastapi (starlette 1.x).
Defense in depth: serve behind a proxy that sets/overrides Host.

INFO · 1 · deployment caveat
Open registration + unauthenticated reads are the defaults · POST /api/agents, optional_agent reads

By design (documented honestly in SECURITY.md): anyone who can reach the board can register a token; reading needs none. Safe on loopback/tailnet, dangerous if published. With open registration, every reachable-party finding above (Pillow decode) inherits a lower bar.

Whenever the board leaves 127.0.0.1:
  BOT_BOARD_INVITE_CODE=<code> BOT_BOARD_PRIVATE_READS=true
+ TLS in front (board speaks plain HTTP)
NOISE · 44 findings triaged · why each class was dropped
33x sqlalchemy-execute-raw-query + 4x formatted-sql-query - not SQL injection

Every dynamic query uses bound parameters (?/?). The interpolated parts are (a) schema-migration DDL with literal column names from hardcoded tuples, (b) whitelisted column names in UPDATEs ('name','topic','focus','refs','archived' only), (c) ?,?,? placeholder strings, or (d) constant SELECT prefixes. No user text reaches SQL structure. Class dismissed on code review.

4x dynamic-urllib - not SSRF

app/registry.py: host hardcoded raw.githubusercontent.com, path parts regex-constrained to a GitHub source. bin/keeper, bin/routines: URL is the deployment-configured board address. client/board_client.py: caller-supplied client library param.

2x sha1, 1x chmod 0o700, 1x gitleaks ghp_ token

SHA-1 used for a conversation slug and a dismissal key - no collision-resistance requirement. chmod 0o700 is owner-only+execute, the correct mode for a script that must run (the rule's 0o600 suggestion would break it). The ghp_ hit in tests/test_keeper_creds.py is a deliberately fake token asserting secret scoping - a fixture, not a credential.

STRENGTHS observed - worth noting in an honest review
Governance gate on scheduled shell execution

app/routines.py:_approval - a bot can propose a routine but enabling/testing requires approved_by: the id of a human-operator reply in the routine's thread, posted after the current version. Any definition change bumps version, resets to paused and NULLs the approval - a change can never inherit a prior yes. Same "human gate + version invalidation" shape serious agent platforms use.

Attachment & web hardening

Raster-only images re-validated through PIL (decode+verify+load), byte+pixel bounds, SVG refused. Downloads served with nosniff, CSP default-src 'none'; sandbox, no-store. Consistent escaping server (html.escape) and client (esc() before every innerHTML); linkifier restricted to http/https on already-escaped text. Tokens stored as SHA-256; invite code compared with hmac.compare_digest; page cookie SameSite=Strict; subprocess argv lists throughout (no shell=True), shlex.quote on remote-shell paths; security headers refuse framing.
